\chapter{System Architecture and Implementation}
\label{ch:system-architecture}

The AquaTrack implementation is organized as a layered mobile health system. The architecture begins with multimodal sensing, continues through preprocessing and dual-pipeline prediction, and ends with backend inference and mobile visualization. This modular structure allows the sensing prototype, data-processing workflow, and deployment interface to be improved independently.

\section{System Architecture}

The proposed system integrates wearable sensing, context-aware processing, and machine learning-based inference for real-time dehydration risk prediction. The architecture is designed for scalability, interpretability, and practical deployment in mobile health environments.

At the input stage, a wearable sensing unit captures physiological and environmental signals relevant to hydration status. These include primary sweat and salivary biomarkers, skin-based measurements such as temperature and conductance, and ambient conditions such as temperature and humidity. The data acquisition module performs signal conditioning, sensor synchronization, analog-to-digital conversion where required, and timestamping before sending structured data for processing.

The incoming data is passed through a preprocessing pipeline that improves consistency and robustness. Missing values are handled using median imputation, extreme values are clipped through winsorization, skewed variables are transformed logarithmically, and feature distributions are normalized through robust scaling. Domain-informed composite features are then constructed to represent physiological stress, hydration state, activity load, and environmental demand.

\section{Context Detection Module}

The context detection module identifies activity intensity, climate class, and sweat availability. This module is important because biomarker readings can be affected by the amount of sweat available and the user's immediate environment. For example, a low-sweat sedentary state may require different interpretation from a high-sweat exercise state. The context module therefore acts as a corrective signal for the biomarker pipeline.

\section{Dual-Pipeline Prediction Engine}

The core prediction engine uses two independent machine learning pipelines. The primary biomarker pipeline classifies hydration state into Low, Medium, and High risk. The secondary context pipeline predicts whether the surrounding conditions indicate low or high contextual dehydration risk. Their outputs are fused using a weighted score so that the final result reflects both biochemical evidence and real-world context.

\section{Backend and Mobile Deployment}

For deployment, the trained models are served through a lightweight FastAPI backend. The API receives structured sensor and context inputs, applies preprocessing, loads the selected model artifacts, performs prediction, and returns a JSON response containing the risk label, confidence score, and recommendation fields.

The mobile application is planned using React Native. It visualizes hydration status, risk history, alerts, and personalized recommendations. The mobile dashboard is designed to make model predictions understandable to users rather than presenting raw sensor data alone.

\section{Monitoring and Interpretability}

The architecture includes monitoring and logging for model performance, drift, and alert history. An interpretability module can expose feature-importance explanations so that users and developers can understand which signals contributed most to a prediction. This is particularly important in health-monitoring systems because users need confidence in the recommendation and developers need visibility into failure cases.

The implemented architecture therefore connects laboratory sensing, data engineering, machine learning, and mobile deployment into a single workflow. The following chapter discusses the observed prototype performance and classification results.
