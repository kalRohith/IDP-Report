\chapter{Project Repository and File Structure}

The AquaTrack repository is organised into five top-level directories separating data, notebooks, trained model artifacts, backend API, and mobile app. This modular structure ensures that the physiological data, machine learning pipelines, and deployment interfaces are managed independently. The repository follows standard software engineering practices to facilitate scalability and cross-modal system maintenance.

\begin{lstlisting}[basicstyle=\ttfamily\small]
AquaTrack/ 
| 
|-- data/ 
| |-- main_data.csv % Primary biomarker dataset (n=90) 
| |-- context_data.csv % Contextual sensor dataset (n=290) 
| 
|-- notebooks/ 
| |-- main_pipeline.ipynb % EDA, preprocessing, target eng, 
| % % feature engineering, ML training 
| |-- context_pipeline.ipynb % Context sensor EDA, binary 
| % % classifier training 
| 
|-- models/ 
| |-- artifacts/ 
| |-- aquatrack_main_classifier.pkl % Trained main pipeline 
| |-- aquatrack_context_classifier.pkl % Trained context pipeline 
| |-- aquatrack_training_medians.pkl % Per-feature medians for 
| % % inference-time imputation 
| |-- aquatrack_selected_features.pkl % Feature list for input 
| % % ordering at inference 
| 
|-- api/ 
| |-- main.py % FastAPI backend - 3 endpoints: 
| % POST /predict 
| % POST /predict-context 
| % GET /medians 
| 
|-- aquatrack-app/ 
 |-- app/ 
 | |-- screens/ % Home, Predict, Results, 
 | | % History, Insights, Settings 
 | |-- components/ % Gauge, RiskBadge, TrendChart, 
 | | % InputCard, ResultCard 
 | |-- services/ 
 | | |-- api.js % All Axios API calls in one file 
 | |-- store/ 
 | | |-- useHistoryStore.js % AsyncStorage CRUD operations 
 | |-- constants/ 
 | |-- colors.js % Design tokens and theme colors 
 | |-- endpoints.js % Backend URL configuration 
 |-- app.json % Expo configuration file
\end{lstlisting}
